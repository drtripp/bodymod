Privacy Policy Draft

This draft describes the current local-first prototype. It is not a final legal policy and must be reviewed before public launch.

Current Prototype Summary

Bodymod is designed around local browser storage. Local accounts, measurements, snapshots, food logs, goals, protocols, workouts, progress photos, face measurement records, and lightweight usage events stay in the browser unless the user exports or shares data.

Data Stored Locally

  • Manual body measurements and unit preferences.
  • Local snapshots, check-ins, goals, protocol logs, workouts, and progress reports.
  • Diet foods, meal templates, fluid logs, and imported CSV rows.
  • Face measurement values derived in browser. The current app stores measurements, not image payloads.
  • Local usage events used for in-browser debugging and product inspection.

Sharing And Export

  • Share links encode measurement values in the URL, so anyone with the link can read those values.
  • JSON exports and encrypted local backups are user-controlled downloads.
  • Progress reports are generated locally for the user's own use.

External Services

  • The prototype calls the bodymod backend for targets, matching, dummy data libraries, and configuration.
  • Diet search can call Open Food Facts for branded food lookup.
  • No production external analytics provider is approved in the current launch decision record.
  • No server account sync or payment processor is implemented in the current prototype.

User Controls

  • Users can clear local usage events from the Method / privacy footnote.
  • Users can delete local snapshots and logs from the app UI.
  • Clearing browser storage removes local prototype data for that browser profile.

Draft review needed: jurisdiction, data-controller identity, retention language, contact address, user rights, analytics, payment, mobile app, and account/sync terms before public launch.
