Methodology

This page documents the current prototype math and data sources used by bodymod. It is written for inspection, not marketing. The current target profiles and many population-chart fields are scaffolds until the source-review work listed in the project backlog is done.

Current Status

  • Target profiles are placeholder estimates, not production reference data.
  • Height, weight, waist, and hip percentiles use NHANES August 2021-August 2023 adult tables.
  • Unsupported population-chart fields remain deterministic scaffold data for interface testing.
  • Strategy corpus entries are informational and not advice, coaching, dosing, or protocol generation.

Measurement Matching

The backend compares the user's measurement set with each target profile. Numeric measurements are converted into normalized distance terms so larger and smaller body fields can be compared in one score. Lower raw distance means a closer match.

The score also includes selected proportion ratios, including shoulder-to-waist and waist-to-hip. Match-priority presets can raise the weight of specific fields or ratios while preserving the same scoring structure.

Raw distance Smaller is closer. This is the internal ranking value used to sort target matches.
Explanation bullets The UI lists the largest measurement gaps so users can inspect why a profile ranked where it did.

Similarity Score

Similarity is a bounded display mapping of the raw distance. The backend returns it with every match, and the frontend displays the rounded percentage.

Current mapping: 100 * exp(-(distance ^ 1.5)). A score of 100 means identical measurements. A score around 95 or higher is intended to sit inside ordinary tape-measure re-entry noise. A score near 40 is roughly a different build within the current placeholder target set.

The mapping is documented in similarity-score-spec.md. It should be recalibrated whenever target profiles, measurement schema fields, or scoring weights change meaningfully.

Percentile Sources

Current percentile output is schema-wide, but not every field has the same evidence level. Height, weight, waist circumference, and hip circumference use official NHANES August 2021-August 2023 adult tables. Other measurement fields still use sex-specific scaffold normal-distribution parameters from backend/app/data/reference.seed.json. The API response label is:

NHANES August 2021-August 2023 adults for height, weight, waist, and hip; approximate scaffold for unsupported fields

NHANES reports weighted means and selected percentiles. The app stores the published percentiles and estimates a standard deviation from the 5th and 95th percentiles only so the current normal-percentile helper can produce bounded approximate percentiles.

Production replacement requires a documented source, license review, field mapping, unit conversion rules, and validation fixtures. The required workflow is recorded in reference-data-curation.md.

Gender Score Charts

The Gender tab compares selected body measurements against two scaffold distribution bands labeled male and female. The chart is a measurement-pattern comparison, not identity inference, medical classification, or attractiveness ranking.

The signed rows are computed by comparing where each measurement sits relative to the scaffold male and female distribution centers. The resulting display is useful for interface testing and trend context, but it must be replaced with vetted population data before any public production claim.

Privacy Boundaries

  • Local accounts, snapshots, goals, and food logs are stored in the browser.
  • Share links encode measurement values in the URL so the link itself carries data.
  • Face measurement scans run locally in the browser and store measurements, not image payloads.
  • Lightweight usage events are local-only and can be cleared from the Method / privacy footnote.
